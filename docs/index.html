Go-native frontend vendoring

tspkg

A small Go tool that vendors ESM-only npm packages directly from the npm registry. No node, no npm, no bun required.

Start using it View on GitHub
go tool tspkg sync 
go get -tool go.flaticols.dev/tspkg/cmd/tspkg

go tool tspkg sync
go tool tspkg verify
!

In active development, and intentionally narrow.

tspkg is not a replacement for npm, pnpm, yarn, or bun. It targets projects that ship browser code via HTML import maps and want their whole frontend toolchain to live inside go.mod.

It intentionally rejects anything that needs transpilation, bundling, or a Node runtime. If you need a general-purpose package manager, use one.

Originally extracted from the weld library, which is still in development and not yet public. tspkg is small and self-contained enough to stand on its own, so it is released ahead of the rest.

00 / Overview

ESM packages, vendored by Go.

tspkg reads package.json, resolves npm packages, vendors browser-ready files, and emits an import map that Go templates can inline.

Fetch

Fetches npm registry tarballs over HTTPS and verifies their registry integrity metadata.

Vendor

Unpacks selected package files into a configurable vendor directory committed or ignored on your terms.

Generate

Writes Go source containing import-map JSON constants, plus a lockfile with per-file SHA-256 hashes.

02 / Use

Install it as a Go tool dependency.

Register tspkg in go.mod, then drive sync and verification from the project directory that contains package.json. 

go get -tool go.flaticols.dev/tspkg/cmd/tspkg
go tool tspkg sync     # resolve, fetch + verify tarballs, vendor, regenerate importmap + lock
go tool tspkg verify   # recompute hashes for the vendored files; non-zero exit on mismatch
go tool tspkg help     # usage

Both commands read package.json from the current working directory.

03 / Manifest

Configuration lives in package.json.

Dependencies use the standard npm field. Project-specific settings live under a namespaced tspkg block, which npm and other tooling ignore. 

{
  "dependencies": {
    "@phosphor-icons/core": "^2.1.0",
    "graphology": "^0.26.0",
    "sigma": "^3.0.0"
  },
  "tspkg": {
    "include": {
      "@phosphor-icons/core": [
        "package.json",
        "assets/duotone/**/*.svg",
        "LICENSE*"
      ]
    },
    "skip":    ["events"],
    "bundled": ["graphology", "sigma"],
    "groups":  { "graph": ["sigma", "graphology"] },

    "paths": {
      "vendor":        "assets/static/vendor",
      "lock":          "tspkg.lock",
      "importmap":     "importmap/importmap.go",
      "vendorUrlBase": "/static/vendor"
    },
    "importmap": { "package": "importmap" }
  }
}
Field Effect
dependencies Standard npm field and the source of truth for packages and version constraints.
include[<pkg>] Doublestar globs relative to the package root. When unset, tspkg vendors everything except obvious noise such as most Markdown files, TypeScript sources, source maps, tests, source folders, and docs.
skip Transitive dependency names to ignore. Useful for phantom CJS deps that bundled distributions do not import at runtime. You take responsibility for runtime correctness.
bundled Packages whose distribution is self-contained. tspkg vendors the package itself but does not walk declared dependencies.
groups[<name>] Buckets package names into named groups. Each group becomes a const <Group> in the generated Go file. Ungrouped packages land in const Base.
paths.vendor Directory for vendored packages. Default: assets/static/vendor.
paths.lock Lockfile path. Default: tspkg.lock.
paths.importmap Output path of the generated Go file. Default: importmap/importmap.go.
paths.vendorUrlBase URL prefix for the vendored tree. Default: /static/vendor. Must start with /static/ so importmap.Rebase can rewrite onto a consumer asset base.
importmap.package Go package name declared at the top of the generated file. Default: importmap.

04 / Outputs

Three artifacts, one repeatable snapshot.

sync regenerates the vendor tree, import-map source, and lockfile from the manifest.

Vendor directory

paths.vendor contains unpacked package files. The README recommends gitignoring it because sync regenerates it.

Generated importmap

paths.importmap exports const Base plus one const <Group> per group. Commit it as a live bundle snapshot consumed by the templ layout.

Lockfile

paths.lock records resolved versions, SRI sha512 integrity, and per-file sha256 hashes used by verify. Commit it.

05 / ESM-only constraint

No CJS fallback, no broken vendor trees.

Packages without a usable ESM entry are rejected with a clear error.

The resolver checks package entrypoints in this order:

  1. exports["."].module preferred, typically the genuine ESM build.
  2. exports["."].browser
  3. exports["."].import
  4. module
  5. main, only if it ends in .mjs or ends in .js with "type": "module".

06 / Consumer wiring

Inline generated maps from Go templates.

Use the generated package from a templ layout or any HTML template. The helper rewrites the canonical /static/ prefix onto the asset base used by the consumer. 

// internal/views/layout.templ
package views

import (
    "yourapp/importmap" // the generated package
    tspkg "go.flaticols.dev/tspkg/importmap"
)

templ Layout(assetBase string) {
    <html>
        <head>
            @templ.Raw(`<script type="importmap">` + tspkg.Rebase(assetBase, importmap.Base) + `</script>`)
            // Optionally inline a heavier group only on pages that need it:
            // @templ.Raw(`<script type="importmap">` + tspkg.Rebase(assetBase, importmap.Graph) + `</script>`)
        </head>
        <body>{ children... }</body>
    </html>
}

07 / Rebase

Serve assets from the path your app uses.

Generated map URLs use the canonical /static/ prefix. importmap.Rebase swaps it for the consumer asset base. 

tspkg.Rebase("/assets/", importmap.Base) // replaces "/static/" with "/assets/"
tspkg.Rebase("/static/", importmap.Base) // no-op
tspkg.Rebase("",         importmap.Base) // no-op

08 / Limitations

Limitations by design.

The project is intentionally scoped to browser-ready ESM packages and public npm registry tarballs.

  • ESM only. No CJS, no UMD, no transpilation, no bundling.
  • Only sha512 SRI hashes are recognized, matching the npm registry's current format.
  • No npm authentication. Only public registry packages.
  • No lockfile-driven offline mode. sync always re-fetches.
  • No watch mode. It is a one-shot build step.

09 / Roadmap

Possible TypeScript transpilation, later.

TypeScript transpilation via typescript-go is on the table. It would let packages that ship .ts sources be vendored as usable .js, but it is not a priority right now because the current ESM-only flow covers the intended use cases.
